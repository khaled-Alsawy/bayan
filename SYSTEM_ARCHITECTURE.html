Where the branches actually land today

Both grounding fallbacks call validated_topic_fallback(), which picks deterministic_contextual_topic_draft() only when supported_facet_summaries is non-empty. That tuple is constructed in exactly one place — planner.py, inside the disabled model-review path — so in the shipped configuration it is always empty and every fallback renders deterministic_topic_source_view_draft(): the attributed source-only reading view.

Forbidden routes — asserted in code, not configurable

ProviderRoutePolicy rejects a completion unless the effective deployment matches exactly: deployment id, gateway provider, effective provider, model id, route policy id, zero-data-retention enforced, provider training off, no subprocessors, not a paid route, no provider-side fallback. Only the model id comes from config/chat_deployments.json; everything else is hard-coded. A mismatch raises ProviderRouteError and the turn fails rather than proceeding on an unverified route.

Quran Foundation is a removed route: no active revision, no runtime code path, an application-level redaction for historical rows, and CHECK constraints on research_response_records, legacy_research_response_records and conversation_turns so a regression fails at the database boundary.

08

The hard invariants

each one is enforced at a single chokepoint
  • Only hydration creates evidence

    Search results are non-citable locations; the assembler rejects any other node that carries evidence.

    evidence.py EvidenceAssembler.assemble()
  • No model-authored canonical text

    Claims must paraphrase. Reproducing Quran, translation or tafsir wording raises CanonicalTextGroundingError.

    synthesis.py GroundingValidator
  • Relevance may narrow, never empty

    A non-empty retrieval can never become an empty evidence set, whatever the relevance implementation.

    relevance.enforce_ranked_relevance_boundary()
  • No semantic expansion past the cited evidence

    A claim naming a high-risk concept — audience, obligation, absolute quantifier — must have that concept's own vocabulary in the evidence that claim cites.

    GroundingValidator._validate_semantic_entailment()
  • Exactly one bounded repair

    Planner, synthesizer and composer each get one retry with accumulated guidance, then fail into a deterministic path. No unbounded loops.

    planner.py · synthesis.py · composition_layer.py
  • The route is asserted, not configured

    ZDR, no provider training, no subprocessors, no paid route, no fallback — hard-coded. Only the model id is data.

    routing.ProviderRoutePolicy
  • UNKNOWN rights are blocked

    Every source right is currently UNKNOWN. Running requires the acknowledged development override; DENIED always blocks; the override is refused in production.

    rights.SourcePolicy.authorize()
  • The narrative is checked against real evidence

    The composer is given claim text and reference labels only. The gate independently checks its output against the turn's actual evidence: quoted Arabic spans, verse references, attributions, hadith-shaped sentences.

    anti_fabrication.py — 4 rules
  • Traces never carry source text

    Detail keys matching secrets or canonical-text names are redacted, depth and breadth are capped, and the trace is forced off in production.

    tracing.TraceRecorder · settings validator
  • Output kind is observed, not claimed

    derive_rendered_output_kind() classifies the rendered blocks, so a template answer cannot be reported as synthesis by the branch that produced it.

    contracts.py

Unverified, and what looks missing

stated rather than guessed

Could not verify

  • All percentages come from HANDOFF.md, not from code or a run made here. No measurement was executed while building this page.
  • Row counts were read from the running local Postgres at build time — current instance state, not a guaranteed deployment shape.
  • The Next.js layer was surveyed at file-tree level only; block ordering in the browser is not verified here.
  • Whether any qf-* rows survive outside source_resources was not audited beyond confirming both have no active revision.

Gaps visible in the architecture

  • No live ranking signal after fusion. Every stage that could reorder candidates — cross-encoder, topic rerank, topic arm — is off, so fused_arm_score is both the first and the final sort key.
  • A dead good-branch. The only producer of SupportedFacetSummary sits in the disabled reviewer, so the branch of deterministic_contextual_topic_draft() that writes real content is unreachable in the shipped configuration.
  • No retry at the embedding boundary. One Cloudflare failure silently downgrades a turn to lexical-only. It is traced, but a single transient 429 costs the dense arm entirely.
  • Tafsir is attached but never required. Topic turns use allow_partial=True, so an Arabic turn whose tafsir lookup returns nothing still passes the requirements check — the tafsir-as-evidence property is best-effort, not enforced.
